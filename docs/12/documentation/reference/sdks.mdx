# SDKs

The official SDKs are thin wrappers around the REST API with a few extras: automatic batching, retries with jitter, offline buffering for mobile, and typed event helpers.

## Quick reference

| Language | Package | Source |
|---|---|---|
| Node.js | `@polaris/sdk` | github.com/polaris-io/polaris-node |
| Python | `polaris-sdk` | github.com/polaris-io/polaris-python |
| Go | `github.com/polaris-io/polaris-go` | github.com/polaris-io/polaris-go |

| Java | `dev.polaris:sdk` | github.com/polaris-io/polaris-java |

## Batching

All server-side SDKs batch events in the background. The default policy is to flush every 250 ms or when the queue reaches 200 events, whichever comes first.

<Accordion>
  <AccordionTab title="Tuning the batch policy" icon="pi pi-sliders-h">

    Both knobs are configurable. Lower latency, smaller batches:

    ```js
    new Polaris({
      token: process.env.POLARIS_TOKEN,
      batch: { maxLatencyMs: 100, maxSize: 50 },
    });
    ```

    Higher throughput, larger batches:

    ```js
    new Polaris({
      token: process.env.POLARIS_TOKEN,
      batch: { maxLatencyMs: 1000, maxSize: 500 },
    });
    ```

  </AccordionTab>

  <AccordionTab title="Flushing manually" icon="pi pi-refresh">

    Call `flush()` before exiting a short-lived process to ensure buffered events are sent.

    ```js
    process.on("beforeExit", async () => {
      await polaris.flush();
    });
    ```

  </AccordionTab>
</Accordion>

## Mobile SDKs

Mobile SDKs (Swift, Kotlin) include an offline event queue backed by the device's filesystem. Events captured offline are persisted and retried on next launch, with a configurable cap to prevent runaway disk usage.

> [!NOTE]
> The Swift SDK uses Core Data; the Kotlin SDK uses Room. Both default to a 5 MB cap and FIFO eviction.

## Versioning

SDKs follow semver. Major versions are released roughly every 18 months and are supported for two majors back. Minor versions are non-breaking. Patch versions are bug fixes only.

> [!WARNING]
> Pin the SDK version in your lockfile. The Polaris API itself is versioned by the URL path (`/v1`), but client-side defaults — batching, retry intervals — can change between SDK minors.
